# Sync and calculation repair acceptance

User: two computers recording Starlink, extension and phone PWA. Preserve design and all existing history. No new router polls.

Before implementation, exercise these service and UI paths:

- Disposable capability pairing: write new snapshot, read via read capability, confirm calculation metadata and source survive the database round trip.
- Older upload after newer upload: reject without replacing saved readings; unknown/read-only tokens cannot write.
- Phone with yesterday's snapshot: label its actual date, never represent old data as today's usage. Poll failures preserve visible evidence and report failure.
- Switch between two explicitly paired recorders: display selected recorder only, no addition of overlapping dish totals, no late response from previous recorder.
- Archive resume after reconnect: each pairing has independent checkpoints; reject malformed restore cursors before saving progress. Existing minutes are never deleted.
- Existing calculation, IndexedDB, collection, build, lint and extension gates must pass. Physical Windows uptime and actual dish reachability cannot be inferred from a successful cloud read.

Backend verification uses scripts/test-phone-sync-backend.mjs with a temporary pair and revokes that pair in finally; no production household rows are mutated. Browser verification uses isolated synthetic snapshots with a mocked API; does not prove hardware capture. Record actual commands/results in final evidence after execution.
